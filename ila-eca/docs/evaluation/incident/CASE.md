# アプリの通信エラーから調査・承認・復旧へ

ローカルKubernetesの合成アプリを使った1件を掲載しています。

## 起点と故障条件

調査の起点はアプリケーションのHTTP通信エラーです。
試験ではServiceのselectorとPodラベルを意図的に不一致にしました。故障注入の条件と、調査開始時の症状は分けて扱います。
Prometheusのアラートをポーリングする中継から、既存の認証付き通知入力へ渡しています。

## 流れ

1. HTTP応答を調べ、Service・EndpointSlice・Pod・GitLabの設定へ調査を広げる。
2. ServiceのselectorとPodラベルの不一致を特定し、修復案を具体化する。
3. GitLabへ提出し、LAB用の試験承認を行う。
4. AWXジョブで修正し、変更後のHTTP応答・接続先・監視状態を再取得する。
5. 元の症状の解消と構成を確認し、RECOVERED_LAB_ONLYとして記録する。

## 結果と条件

- Astraの調査6回、修復計画の具体化1回で、限定LABでの復旧を確認しました。
