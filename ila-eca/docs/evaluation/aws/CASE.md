# コンテナ環境のAWS移行構成案

公開用の合成API・ワーカー環境の1ケースを掲載しています。

## 入力と評価

既存のKubernetes上に、Webの要求を受けるAPIと、キューからジョブを受け取るワーカーがあります。
既存の保存先・キュー・データベースと業務操作を維持し、実行基盤・主体・通信・権限・移行・切戻しが一つの案として整合するかを確認しました。

| モデル | 完走時間 | レビュー結果 |
|---|---:|---|
| GPT-6.2 Astra | 162.953秒 | 成立条件を示した論理設計案として合格 |
| GPT-6.2 Sol | 69.797秒 | 成立条件を示した論理設計案として合格 |

両案はEKSとECS Fargateを比較し、Kubernetes固有の依存がないこと等を条件にECS Fargateを採用しています。
主体別のIAM権限、公開範囲、業務操作、処理中の状態と切戻しをレビューしています。
AWSへの実構築や、運用環境での動作成功を確認したケースではありません。
